S-Docs UX Prototypes

Interactive design prototypes for the S-Docs e-signature platform.

Headless

1 prototype

Document Scenarios

Admins define which records get which documents — and the phrasings people actually use to ask for them — without writing a filter, a query or a field API name. A seven-step wizard ending in a live preview of the whole conversation, as it would happen in Claude or Slack. Covers multi-template packs, runtime inputs, e-signature confirmations, and generating row-by-row versus all at once.

Claude Sales Proposal

A rep asking Claude to draft a proposal: the S-Docs Proposal Agent disambiguates which opportunity, confirms sources & content, then drafts a proposal with a linked execution audit.

Claude Investment Proposal

An advisor asking Claude for a quarterly investment review: the agent disambiguates which client household, confirms sources & sections, then drafts a chart-rich portfolio review with a linked execution audit.

Teams Proposal Agent (Autonomous)

An agent that listens: it notices a customer emailed asking for a proposal, proactively pings the rep in Teams, confirms the details, then drafts the proposal with a linked execution audit.

Slack Contract Review Agent (Autonomous)

While the rep is heads-down in a channel, the agent notices a customer sent back redlines, then confirms before showing key changes and a playbook-driven risk score shift, plus a linked execution audit.

Contract Playbook Review

An "Analyze" task use case: reviewing a contract against a weighted playbook (IP protection, termination for convenience, etc.) with a risk score and drill-down citations.

Agent Catalogue (End User)

A non-builder's view: browse and run agents shared enterprise-wide, by your team, or your own — and clone one to customize if you have creator access.

Admin Console

Governance for the agent platform: role-based permissions, a connector allowlist, an audit log, and policy alerts.
